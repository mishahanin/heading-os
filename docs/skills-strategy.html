/deep-think [problem]Strategy

Auto-routes from natural language (and engages proactively) · saves strategic sessions to outputs/thinking/

What it is. A structured sequential reasoning engine that breaks a complex decision into visible, numbered thought steps, surfacing every assumption and ending with a maritime-framed course recommendation.

What it does. Runs through named stages (Problem Definition, Assumptions Surfaced, Research/Evidence, Analysis with Path A/B/C branching, Revision, Synthesis, Heading Recommendation) at a depth of quick, standard, or deep. It can optionally pull 2-5 named elicitation methods via scripts/elicit.py. The output closes with a Course, Confidence (HIGH/MEDIUM/LOW), Key risk, and a concrete course correction; strategic standard/deep sessions persist to outputs/thinking/YYYY-MM-DD-[topic].md. It is a thinking layer that feeds /deal-strategy, /create-plan, /meeting-prep, and /investor-pitch.

How to use it. Use before generating a deliverable when reasoning quality matters, or let it engage itself on multi-variable, high-stakes problems. For a simple question just answer it; for independent opinions from other models use /council.

/deep-think enter the new market direct or through a partner, given the tender deadline
"what are we missing on this pricing call"

Customize. depth is quick/standard/deep. Per-exec overrides (default depth, currency, output path) resolve via scripts/resolve_customization.py (layout in config/skill-custom/README.md). Elicitation methods are catalogued in reference/elicitation-methods.md.

/council [question] | --critique [draft]Strategy

Auto-routes from natural language · saves transcript to outputs/operations/council/

What it is. A second-opinion advisor that consults an outside model for an independent view on a hard or high-stakes call, presented side-by-side with Claude's own view. The CEO decides, there is no synthesized final answer. The default roster is Kimi k3; Gemini and Grok are opt-in.

What it does. Runs in independent mode (the models see the problem fresh, without Claude's reasoning) or critique mode (they stress-test a draft). It dispatches the selected consult scripts (scripts/kimi-consult.py by default, plus scripts/gemini-consult.py and scripts/grok-consult.py when asked) in a single parallel message, distills each verbatim response into a traceable bullet block, adds Claude's independently reached view, then a where-we-agree/disagree paragraph. The transcript persists to outputs/operations/council/, and a final line asks the CEO which answer landed best (recorded via scripts/council-record-verdict.py and aggregated).

How to use it. Use for a hard call where an independent view is worth the latency, and add --all when cross-model disagreement is itself the signal. For Claude reasoning alone use /deep-think; for Claude plus the curated knowledge brain use /odin.

/council should we sign the Acme Corp reseller deal or stay direct
/council --critique "draft message text to stress-test"
"second opinion on this pricing"

Customize. Requires GEMINI_API_KEY, XAI_API_KEY, and OLLAMA_API_KEY in .env. Flags: --gemini/--grok/--all (add voices to the default roster), --gemini-only/--grok-only/--kimi-only (run one), --no-gemini/--no-grok/--no-kimi (drop one), per-model --gemini-model/--grok-model/--kimi-model, plus --temperature, --max-tokens, and --no-log.

/deal-strategy [prospect]Strategy

Auto-routes from natural language · writes to outputs/negotiations/

What it is. A full deal strategy analysis for a specific prospect: prospect intelligence, competitive positioning, a pricing recommendation, Voss-informed objection handling, and recommended next steps in one briefing.

What it does. Reads the business, strategy, DPI market intelligence, growth playbook, and pipeline context files, then works through seven phases (prospect intelligence, competitive analysis, positioning, pricing, Voss objection handling, next steps, brain audit). It keeps an append-only memlog at outputs/negotiations/[prospect]/.memlog.md (via scripts/memlog.py) so work survives a context compaction, and writes the brief to the same directory. On the CEO workspace it can cite Odin principles via scripts/odin-principles.py, and it closes with a /brain-audit footer reporting source freshness and contradictions.

How to use it. Use to build the win plan for a specific opportunity. For competitor comparison alone use /competitor-intel; for market intel use /market-brief.

/deal-strategy Acme Corp
"how do we win the Acme Corp deal"

Customize. Positioning and pricing draw from reference/billion-growth-playbook.md and reference/dpi-market-intelligence.md; competitor profiles and geopolitical context from those and reference/geopolitical-landscape.md. Odin principle citation is brain-gated (CEO workspace only) and skips silently elsewhere.

/investor-pitch [investor_type]Strategy

Auto-routes from natural language · returns deck content (read-only, no file write)

What it is. Full investor pitch deck content: the investment narrative arc, a slide-by-slide structure with key messages and speaker notes, and a data appendix, tuned to the investor type.

What it does. Reads the business, current-data, strategy, growth-playbook, market-intelligence, geopolitical, and voice context files, then produces three phases: the Problem-to-Ask narrative arc, a 14-slide structure (title, one-sentence key message, bullets, and speaker note per slide), and a supporting data appendix. Investor type (strategic, venture, sovereign fund, angel, corporate VC) tunes the framing. It optionally runs the /editorial-review structural checklist over a long assembled narrative. Output is text content for Misha to adapt and present, not a rendered file.

How to use it. Use to prepare materials for an investor meeting or fundraise. For a progress update to existing investors use /investor-update; to render the slides as PPTX use /pptx-generator.

/investor-pitch venture
"prepare a fundraising deck for a sovereign fund"

Customize. Set investor_type, round_context, audience, and format (deck_outline/full_content/speaker_notes_only, default full content). Narrative and metrics are grounded in reference/billion-growth-playbook.md, the context files, and validated against datastore/INDEX.md.

/voss [counterpart] [situation]Strategy

Auto-routes from natural language · writes to outputs/negotiations/

What it is. A tactical negotiation and conversation coaching engine based on Christopher Voss's FBI methodology: it produces a situation-specific playbook for a high-stakes conversation.

What it does. Reads the Voss reference, voice guide, people, and pipeline files (plus the counterpart's CRM file if one exists), then builds five phases: intelligence and profiling (negotiator type, power dynamics), an accusation audit with preemptive labels, 8-12 calibrated questions, a tactical playbook (mirroring map, labeling scripts, "That's Right" pathway, Black Swan hypotheses, Ackerman plan), and scenario mapping. It saves the playbook to outputs/negotiations/YYYY-MM-DD-{counterpart}.md and logs a Note to the counterpart's CRM file if present.

How to use it. Use for deep per-conversation prep before a negotiation, difficult talk, or sensitive call. Note the Voss principles also run always-on across all outbound comms via the voss rule; this skill is the dedicated deep prep.

/voss Jane Doe (Acme Corp) renewal price pushback
"prepare me for this difficult conversation"

Customize. Set counterpart, situation, goal, and optional tension. The full methodology (Ackerman Model, tactical phrases) lives in reference/voss-negotiation.md; playbook language matches reference/misha-voice.md. Non-round numbers are enforced in any pricing.

/state-check [function]Strategy

Auto-routes from natural language · returns a one-page assessment (read-only, no file write)

What it is. A diagnostic assessment of one workspace function or the whole system, run as a 15-minute State Check in the Navigation Principle sense: operational state, drift, and course corrections rather than rigid pass/fail targets.

What it does. Reads the operational-state-model, the state-check guide, current-data, and pipeline, then answers the four State Check questions (Sea State, Current State, Heading Check, Course Corrections) for the chosen function (sales, product, partnerships, tribe, research, or company-wide). Output is one page max: current state in a sentence, an on-heading / slight-drift / significant-drift verdict, a sea-state summary, up to three behavioral course corrections, and the next check timing.

How to use it. Use to diagnose whether a function is holding its operational state. For the morning briefing use /dashboard, for the full context load use /prime, for the end-of-week review use /weekly-review.

/state-check sales
"how are we doing on partnerships"

Customize. Set function and optional situational context. The operational states per function are defined in outputs/operations/workspace/31c-operational-state-model.md; the four-question format in reference/state-check-guide.md.

/proposal [type] [recipient]Strategy

Auto-routes from natural language (locked corporate doctype, changes require CEO approval) · writes to outputs/documents/{sender}/proposal/

What it is. Produces a branded 31C commercial proposal (PDF + DOCX) for a sales, partnership, channel, or government deal from the locked corporate template.

What it does. Loads the brand stack (reference/corporate-style-guide.md, terminology, voice, Voss rules) and drafts a four-page deliverable: dark cover, executive opening plus opportunity, solution plus proof, commercial terms plus next steps, with Voss-precise pricing (no round numbers). How to use it. Use it for a commercial offer with pricing; for an MOU, LOI, or term sheet use /partnership-doc, for a formal letter without pricing use /corporate-letter, and for a tender use /rfp-response.

/odin [mode] [source or question]Strategy 🔒

Auto-routes on "Odin" as a name or address (CEO-only, never synced) · writes to knowledge/odin-brain/

What it is. A persistent AI advisor with a curated, CEO-only knowledge brain that ingests books, articles, and videos, builds principles and positions, and gives referenced first-person advice with a mandatory Challenge section.

What it does. Runs nine modes: learn (ingest a source and extract principles), consult (default, brain-grounded advice), recall, reflect, teach, log (record a dated episode), collect (scan business threads for episodes), compile (lint the brain plus ZK), and skill-proposal. All writes land only in the knowledge/odin-brain/ brain; after any write it refreshes INDEX.md and rebuilds the associative memory index (scripts/memory-index.py build) so new notes are recallable, then runs the hidden-character scan.

How to use it. Use it to advise from or grow the curated brain, or to log episodes; for structured reasoning without the brain use /deep-think, and for a generic note use /zk. Do not trigger on "odin" as the Russian numeral "one".

/odin consult should we sign an exclusive channel deal in this region
"ask Odin what he thinks about the pricing shift"

Customize. Brain lives entirely under knowledge/odin-brain/ (sources, principles, positions, episodes, conflicts), with mode pipelines in references/mode-catalog.md and file templates in references/templates.md. The index rebuild depends on a local ollama bge-m3 model; the cadence-nudge Telegram target is set via the engine .env key ODIN_CADENCE_TELEGRAM_TARGET. CEO-only, never published to corporate or execs.

/recall <what to recall> [--collection content|code|all] [--layer NAME]Strategy

Auto-routes from natural language (CEO-only, never synced) · read-only, cites file paths (no writes, no sends)

What it is. Workspace-wide semantic recall: finds past decisions, briefs, contacts, and notes by meaning across the whole workspace, then answers only from retrieved sources with path citations or says "not in memory".

What it does. Refreshes the local associative-memory index incrementally (scripts/memory-index.py build, ollama bge-m3 hybrid dense plus BM25, on-machine, zero API cost), queries it with --json across the Odin brain, threads, CRM, LinkedIn, context, reference, plans, outputs, knowledge, and datastore extracts, then reads the top cited files and composes a cited answer. On a threshold gap it reports the gap plainly rather than guessing; it structurally air-gaps the vault and personal-thread branch.

How to use it. Use it to surface something the workspace already knows by meaning; for Odin-brain-only advice use /odin recall, for external intel use /osint, to capture a new note use /zk, and for exact-string search use Grep.

/recall where did we land on the Acme Corp pricing --collection content
"have we touched Northgate Capital before"

Customize. The --collection flag switches between content (default, what we know or decided), code (skills and rules), or all; --layer NAME pins one source layer (for example odin, thread, crm, context, outputs). The engine (scripts/memory-index.py) is cross-lingual RU/EN and runs entirely local. CEO-only, never synced to executives.
